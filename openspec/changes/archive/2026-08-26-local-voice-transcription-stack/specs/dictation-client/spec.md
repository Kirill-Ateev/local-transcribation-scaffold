# Delta spec: dictation-client

## Purpose

Определяет поведение клиента диктовки на MacBook: OpenWhispr как custom provider поверх сервиса на DGX Spark — от нажатия хоткея до вставки текста в позицию курсора.

## ADDED Requirements

### Requirement: Сценарий push-to-talk

Клиент ДОЛЖЕН (MUST) поддерживать сценарий: удержание глобального хоткея → запись с микрофона → отпускание → отправка аудио на сервер → вставка полученного текста в текущую позицию курсора активного приложения. Вставка НЕ ДОЛЖНА (MUST NOT) требовать ручных действий (копипаст) и НЕ ДОЛЖНА (MUST NOT) сбивать фокус приложения.

#### Scenario: Диктовка в браузер

- **WHEN** пользователь удерживает хоткей, произносит фразу в поле ввода браузера и отпускает клавишу
- **THEN** расшифрованная фраза появляется в поле ввода там, где стоял курсор, фокус остаётся в браузере

#### Scenario: Диктовка в терминал

- **WHEN** пользователь диктует короткую фразу при сфокусированном терминале
- **THEN** текст вставляется в строку терминала, но не отправляется на выполнение (без автоматического Enter)

### Requirement: Подключение к сервису через custom provider

Клиент ДОЛЖЕН (MUST) быть настроен как OpenAI-совместимый custom provider с указанием базового URL сервиса на DGX Spark и Bearer-токена. Конфигурация ДОЛЖНА храниться локально на клиенте; токен не коммитится в репозиторий.

#### Scenario: Провайдер указывает на Spark

- **WHEN** в настройках клиента выбран custom provider c URL `http://<spark>:<port>/v1` и токеном
- **THEN** запросы клиента уходят на сервис на Spark, а не в облако и не в локальную модель

### Requirement: Целевая латентность диктовки

Для диктовки длительностью до 10 секунд по локальной сети время от отпускания клавиши до вставки текста ДОЛЖНО составлять не более 3 секунд в медиане. Замер ДОЛЖЕН (MUST) быть воспроизводим (лог/метрика клиента или внешний замер).

#### Scenario: Короткая фраза по LAN

- **WHEN** пользователь диктует 5-секундную фразу, находясь в той же сети со Spark
- **THEN** текст вставляется не позднее 3 секунд после отпускания клавиши (медиана по 10 попыткам)

### Requirement: Видимость ошибок бэкенда

Если сервер недоступен, отвечает ошибкой авторизации или таймаутом, клиент ДОЛЖЕН (MUST) явно уведомить пользователя (уведомление/индикатор) и НЕ ДОЛЖЕН (MUST) (MUST NOT) вставлять пустой или мусорный текст.

#### Scenario: Spark выключен

- **WHEN** пользователь делает попытку диктовки при недоступном сервере
- **THEN** появляется уведомление об ошибке связи, текст в приложение не вставляется

#### Scenario: Неверный токен

- **WHEN** сервер отвечает 401 из-за несовпадения токена
- **THEN** пользователь видит понятное сообщение об ошибке авторизации

### Requirement: Разрешения macOS задокументированы и проверены

Настройка клиента ДОЛЖНА (MUST) включать выдачу необходимых разрешений macOS (микрофон, Accessibility/вставка текста), чтобы сценарий работал после первичной настройки и перелогина.

#### Scenario: Чистая установка

- **WHEN** новый пользователь следует инструкции настройки клиента
- **THEN** после выдачи разрешений и выбора провайдера первая же диктовка вставляет текст корректно
