# Proposal: local-voice-transcription-stack

## Why

Нужна приватная диктовка уровня Wispr Flow на своём железе: нажал клавишу — сказал — текст появился в позиции курсора, полностью локально, без облаков. Основной язык — русский с английскими техническими терминами («открой деплой в Cursor», «запусти kubectl rollout»). Есть простаивающий DGX Spark (ARM64 + Blackwell, 128 ГБ unified memory) и MacBook — связка «тяжёлый сервер + лёгкий клиент» закрывает задачу без компромиссов по качеству модели.

## What Changes

- **Новый STT-сервис на DGX Spark**: батчевый REST-сервис с OpenAI-совместимым эндпоинтом `POST /v1/audio/transcriptions`. Единственная резидентная модель — Whisper large-v3 (встроенная пунктуация) через рантайм faster-whisper по пути `paruparu/faster-whisper-dgx-spark` (адаптация CTranslate2 под GB10). Предобработка — Silero VAD (обрезка тишины, сегментация). Поддержка длинных аудио (часовые записи) через внутреннее чанкование.
- **Клиентская диктовка на MacBook без разработки своего приложения**: OpenWhispr в режиме custom provider, указывающий на сервис на Spark. Push-to-talk → запись → вставка текста в фокус курсора.
- **Auth и сеть**: Bearer-токен; доступ только внутри локальной сети, без VPN/TLS-обвязки.
- **Целевой рантайм на DGX Spark** — Docker-окружение из рецепта `paruparu/faster-whisper-dgx-spark` (CTranslate2 с CUDA-сборкой под GB10), внутри которого работает наш сервис; собственное окружение venv+systemd сохраняется как альтернатива.
- **Eval-харнесс**: фиксированный набор фраз (чистый RU / RU+EN термины / числа / идентификаторы команд) + скрипт подсчёта WER/CER для выбора и регрессионной проверки модели и настроек.

### Явно вне скоупа (зафиксировано решениями)

- Стриминговые partials во время речи — только батч после отпускания клавиши.
- LLM-постобработка текста (чистка мусора, команды форматирования) — пунктуацию и базовое качество даёт сама модель Whisper.
- Диаризация спикеров и UI таймкодов.

## Capabilities

### New Capabilities

- `transcription-service`: поведение STT-сервиса на DGX Spark — OpenAI-совместимый батчевый API, приём коротких диктовок и длинных аудио, VAD-предобработка, управление языком, авторизация, обработка ошибок.
- `dictation-client`: поведение клиента на MacBook — конфигурация OpenWhispr как custom provider поверх сервиса на Spark, сценарий push-to-talk от хоткея до вставки текста, требования к латентности и разрешениям macOS.
- `deployment`: установка и эксплуатация стека — подготовка окружения DGX Spark (ARM64/Blackwell), запуск сервиса как постоянного процесса, сетевой доступ в пределах локальной сети, управление токеном, проверка работоспособности.

## Impact

- **Репозиторий**: новый код в `server/` (FastAPI-сервис, бэкенд faster-whisper + VAD), `client/` (конфиг/документация OpenWhispr), `eval/` (набор фраз, скоринг), `deploy/` (юниты, инструкции). Репозиторий пуст, ломать нечего — все изменения добавляющие.
- **Зависимости**: Python 3.11+, FastAPI/Uvicorn, faster-whisper (CTranslate2), silero-vad, PyTorch CUDA (aarch64, sm_121); на клиенте — существующее приложение OpenWhispr (macOS).
- **Внешние системы**: только локальная сеть между MacBook и Spark; без внешних сервисов, VPN и облаков. Облачные API не используются.
- **Ключевое допущение-риск**: репозиторий `paruparu/faster-whisper-dgx-spark` даёт рабочий faster-whisper на GB10 — проверяется первым спайком до построения остального; фолбэк описан в design.md.

## Assumptions

- Использование устройств последовательное (несколько устройств, но не одновременно) → сериализация запросов допустима, сложный батчинг не нужен.
- Длинные аудио транскрибируются синхронным запросом с большим таймаутом (CLI/curl со стороны пользователя); асинхронные джобы — будущая опция.
- Язык по умолчанию — русский (`language=ru`), английские термины модель выводит латиницей; параметр переопределяется в запросе.
- Спайк рантайма, развёртывание на DGX Spark/MacBook и приёмочные проверки выполняются владельцем отдельно; задачи change покрывают код, инструменты и проверки, выполнимые в среде разработки.
- Целевой способ запуска на Spark — рецепт D1 (Docker); собственное venv-окружение — альтернатива, а не основной путь.
