# transcription-service Capability

## Purpose

Определяет поведение STT-сервиса на DGX Spark: батчевое преобразование речи в текст через OpenAI-совместимый API для коротких диктовок и длинных аудио, с авторизацией токеном и предобработкой звука.

## Requirements

### Requirement: OpenAI-совместимый эндпоинт транскрибации

Сервис ДОЛЖЕН (MUST) предоставлять эндпоинт `POST /v1/audio/transcriptions`, принимающий аудиофайл (multipart/form-data, форматы WAV/MP3/FLAC/M4A/OGG и PCM16 16 кГц моно) и возвращающий JSON в формате ответа OpenAI (`{"text": ...}`, опционально `segments`/`language`/`duration`). Клиенты, говорящие на протоколе OpenAI Audio API, ДОЛЖНЫ (MUST) работать с сервисом без модификации. Для клиентов, добавляющих к Server URL путь без префикса `/v1` (контракт Self-Hosted провайдера OpenWhispr: `POST {Server URL}/audio/transcriptions`), сервис ДОЛЖЕН (MUST) принимать тот же запрос по алиасу `/audio/transcriptions`; аналогичный алиас ДОЛЖЕН (MUST) существовать для `GET /v1/models` (`/models`).

#### Scenario: Клиент без префикса /v1

- **WHEN** клиент (OpenWhispr) отправляет POST на `/audio/transcriptions` с файлом и токеном
- **THEN** сервис обрабатывает запрос так же, как `/v1/audio/transcriptions`, и отвечает HTTP 200 с `text`

#### Scenario: Короткая диктовка

- **WHEN** клиент отправляет POST с 5-секундным WAV-файлом речи с явным `language` (например, `zh` или `en`)
- **THEN** сервис отвечает HTTP 200 c JSON, содержащим поле `text` с расшифровкой, включающей пунктуацию

#### Scenario: Английский термин внутри фразы на другом языке

- **WHEN** в диктовке присутствует смешанная фраза с английскими терминами (code-switching — сильная сторона Breeze-ASR-25)
- **THEN** `text` содержит английские термины в оригинальной латинской записи без транслитерации

### Requirement: Авторизация по Bearer-токену

Сервис ДОЛЖЕН (MUST) по умолчанию требовать заголовок `Authorization: Bearer <token>` для всех эндпоинтов транскрибации; режим задаётся конфигурацией (`AUTH_REQUIRED`, по умолчанию включён). При отключённой авторизации (`AUTH_REQUIRED=0` — доверенная LAN для клиентов без возможности задать заголовок, например OpenWhispr Self-Hosted) сервис ДОЛЖЕН (MUST) принимать анонимные запросы на те же эндпоинты, включая алиасы без `/v1`. Токен ЗАДАЁТСЯ (MUST) через конфигурацию окружения и НЕ хранится в репозитории. Режим ДОЛЖЕН (MUST) быть виден в `GET /health` (`auth_required`).

#### Scenario: Запрос без токена при включённой авторизации

- **WHEN** клиент отправляет запрос на `/v1/audio/transcriptions` без заголовка Authorization или с неверным токеном (AUTH_REQUIRED=1, по умолчанию)
- **THEN** сервис отвечает HTTP 401 без запуска инференса

#### Scenario: Запрос с валидным токеном

- **WHEN** клиент отправляет запрос с корректным токеном из конфигурации сервера
- **THEN** запрос обрабатывается штатно

#### Scenario: Авторизация отключена

- **WHEN** конфигурация задана с `AUTH_REQUIRED=0` и клиент отправляет запрос без заголовка Authorization
- **THEN** запрос обрабатывается штатно (HTTP 200), при этом `/health` показывает `auth_required: false`

### Requirement: Предобработка аудио через VAD

Сервис ДОЛЖЕН (MUST) обрезать тишину и сегментировать входное аудио при помощи VAD перед подачей в модель, чтобы снизить латентность и подавить галлюцинации модели на паузах и тихих фрагментах.

#### Scenario: Диктовка с длительной тишиной на концах

- **WHEN** клиент отправляет запись, где речь занимает 3 секунды, а тишина — по 4 секунды до и после
- **THEN** инференс выполняется только над речевым фрагментом и `text` не содержит повторяющихся фраз-галлюцинаций

#### Scenario: Полностью тихий файл

- **WHEN** клиент отправляет аудио без речевых фрагментов
- **THEN** сервис отвечает HTTP 200 с `text` равным пустой строке (не зависает и не галлюцинирует)

### Requirement: Дефолтный промпт и постобработка capglue

Сервис ДОЛЖЕН (MUST) подставлять дефолтный `initial_prompt` (promptv3: инструкция сохранять английские термины латиницей), если клиент не прислал собственный `prompt`. Сервис ДОЛЖЕН (MUST) применять к итоговому тексту регекс-постобработку capglue — починку склеек предложений (специфика Breeze-ASR-25), не повреждая camelCase-идентификаторы, домены и числа. Оба поведения ДОЛЖНЫ (MUST) отключаться конфигурацией (`INITIAL_PROMPT=`, `CAPGLUE=0`).

#### Scenario: Склейка предложений починена

- **WHEN** транскрипт модели содержит склейку вида «кулинариейПочему»
- **THEN** клиент получает текст «кулинарией. Почему» (точка, пробел, заглавная)

#### Scenario: Техническая лексика не повреждена

- **WHEN** транскрипт содержит camelCase-идентификатор, домен или число (например, «используй useState на example.com, версия 3.14»)
- **THEN** такие фрагменты возвращаются без изменений

#### Scenario: Постобработка отключается

- **WHEN** конфигурация задана с `CAPGLUE=0`
- **THEN** текст возвращается в том виде, в каком его выдала модель

### Requirement: Транскрибация длинных аудио

Сервис ДОЛЖЕН (MUST) принимать аудио произвольной длительности (включая записи более часа), внутренне разбивать его на чанки и возвращать полную связную расшифровку за один синхронный запрос. Память сервиса НЕ ДОЛЖНА (MUST NOT) расти пропорционально длительности файла.

#### Scenario: Часовая запись

- **WHEN** клиент отправляет 60-минутный MP3 с валидным токеном
- **THEN** сервис возвращает полную расшифровку одним ответом, не падая по памяти и не теряя фрагменты в местах склейки чанков

#### Scenario: Длительный запрос не рвёт сервис

- **WHEN** во время обработки часового файла приходит короткий запрос диктовки от другого клиента
- **THEN** второй запрос завершается корректно (обработан после текущего либо параллельно без повреждения результатов обоих)

### Requirement: Резидентная модель

Сервис ДОЛЖЕН (MUST) загружать модель один раз при старте и держать её в памяти между запросами. Повторные запросы НЕ ДОЛЖНЫ (MUST) (MUST NOT) вызывать перезагрузку весов.

#### Scenario: Второй запрос быстрее первого

- **WHEN** после старта сервиса обработаны две одинаковые короткие диктовки подряд
- **THEN** время обработки второго запроса существенно меньше первого (первый включает прогрев) и в логах нет повторной загрузки весов

### Requirement: Одна резидентная модель и управление языком

Сервис ДОЛЖЕН (MUST) обслуживать единственную настроенную модель — по умолчанию `SoybeanMilk/faster-whisper-Breeze-ASR-25` (CT2-конверсия MediaTek Breeze-ASR-25), задаваемую конфигурацией `WHISPER_MODEL` — загруженную в память один раз при старте. Параметр запроса `model` ДОЛЖЕН (MUST) приниматься для совместимости с протоколом OpenAI, но НЕ ДОЛЖЕН (MUST) (MUST NOT) приводить к загрузке или переключению моделей. Параметр `language` ДОЛЖЕН (MUST) управлять языком расшифровки; значение по умолчанию — `auto` (автоопределение языка моделью), настраивается `DEFAULT_LANGUAGE`.

#### Scenario: Запрос с дефолтами

- **WHEN** клиент отправляет аудио без параметров `language` и `model`
- **THEN** расшифровка выполняется резидентной моделью, язык определяется автоматически, ответ содержит распознанный язык

#### Scenario: Переопределение языка

- **WHEN** клиент отправляет аудио с `language=en`
- **THEN** расшифровка выполняется с английским языком

#### Scenario: Значение model игнорируется как селектор модели

- **WHEN** клиент отправляет запрос со значением `model`, отличным от имени развёрнутой модели
- **THEN** запрос успешно обрабатывается единственной резидентной моделью без загрузки дополнительных весов

### Requirement: Понятные ошибки API

Сервис ДОЛЖЕН (MUST) возвращать информативные коды ошибок: 401 (нет/неверный токен), 400 (неподдерживаемый формат, пустой файл, битый multipart), 413 (файл сверх лимита размера), 503 (модель ещё не загружена после старта).

#### Scenario: Неподдерживаемый формат

- **WHEN** клиент отправляет файл неподдержанного типа (например, `.txt`)
- **THEN** сервис отвечает HTTP 400 с JSON-ошибкой, описывающей допустимые форматы

#### Scenario: Сервис ещё прогревается

- **WHEN** запрос приходит сразу после старта процесса, пока веса ещё грузятся
- **THEN** сервис отвечает HTTP 503 с полем `Retry-After`, не падая

### Requirement: Проверка живости сервиса

Сервис ДОЛЖЕН (MUST) предоставлять GET `/health`, доступный без токена, возвращающий статус готовности (загружена ли модель, версия сервиса). Клиент использует его для отображения доступности бэкенда.

#### Scenario: Health-check после старта

- **WHEN** клиент запрашивает `/health` после полной загрузки модели
- **THEN** ответ HTTP 200 содержит признак готовности модели

#### Scenario: Health-check во время загрузки

- **WHEN** клиент запрашивает `/health`, пока модель ещё загружается
- **THEN** ответ отражает неготовность (статус/поле loading), но сам сервис отвечает
